### 8. Implementation of Ergonomic Decision Shortcuts (`SystemOneCore/Ergonomics`)
- **`Choosable.swift` (`Sources/SystemOneCore/Ergonomics/Choosable.swift`)**:
  - Defined the public protocol `Choosable: CaseIterable, Hashable, Sendable`.
  - Requirements: `var optionIdentifier: String { get }` and `var optionDescription: String? { get }`.
  - Default implementations provided:
    - Enums conforming to `RawRepresentable where RawValue == String` default `optionIdentifier` to `rawValue`.
    - General Swift enums default `optionIdentifier` to `"\(self)"`.
    - `optionDescription` defaults to `nil`, allowing optional natural-language semantic guidance per case.
- **`Choice.swift` (`Sources/SystemOneCore/Ergonomics/Choice.swift`)**:
  - Defined generic value container `Choice<Option: Hashable & Sendable>: Sendable, Equatable`.
  - Encapsulates:
    - `value: Option`: The winning selected option.
    - `confidence: Double`: Calibrated model confidence (0.0 to 1.0).
    - `distribution: [Option: Double]`: Probability mass across all evaluated candidate cases.
    - `rawContent: GeneratedContent`: Raw Foundation Models response payload.
    - `probability(of option: Option) -> Double`: Convenience lookup helper.
- **`ScoreResult.swift` (`Sources/SystemOneCore/Ergonomics/ScoreResult.swift`)**:
  - Defined container `ScoreResult: Sendable, Equatable`.
  - Encapsulates:
    - `value: Double`: Probability-weighted continuous mean score (e.g., `2.75` across levels 0...3).
    - `mostLikelyIndex: Int`: Zero-based index of the level with highest probability.
    - `mostLikelyLevel: String`: Descriptive label of the winning level.
    - `probabilities: [Double]`: Calibrated probability distribution across all levels.
    - `confidence: Double`: Overall calibrated confidence score.
    - `levels: [String]`: The evaluated rubric levels.
- **`DynamicDecisionSchema.swift` (`Sources/SystemOneCore/Ergonomics/DynamicDecisionSchema.swift`)**:
  - Implemented dynamic runtime schema construction via `DynamicGenerationSchema`:
    - `makeBinarySchema(instructions:whenTrue:whenFalse:)`: Synthesizes an object schema with a required `Bool` property named `"decision"` and qualified instructions.
    - `makeChoiceSchema(instructions:options:)`: Synthesizes an `anyOf` schema across candidate option names, embedding formatted option descriptions into the instructions glossary.
    - `makeScoreSchema(instructions:levels:)`: Synthesizes an object schema with an integer property constrained by `.range(0...maxLevel)` and an embedded rubric map.
  - Ensures seamless translation through `SchemaTranslator` into `noul`, `choice`, and `score` primitives.
- **`LanguageModelSession+SystemOne.swift` (`Sources/SystemOneCore/Ergonomics/LanguageModelSession+SystemOne.swift`)**:
  - Extended Apple's `LanguageModelSession` with 4 high-level async shortcuts:
    - `probability(of:state:criteria:) async throws -> Double`
    - `choice(_:from:state:) async throws -> Choice<Option>` (for `Choosable` enums)
    - `choice(_:options:state:) async throws -> Choice<String>` (for dynamic runtime strings)
    - `score(_:levels:state:) async throws -> ScoreResult` (for ordinal rubrics)
  - Integrated robust fallback parsing for probability and confidence metadata from `response.probability(for:)`, `response.probabilities`, `response.scoreValue(for:)`, and `response.content`.

### 12. Architecture & Implementation of `ProxyTransport` (`Sources/JevFoundationModels/Transport/`)
- In accordance with the zero-external-dependency mandate ([Tech Note 0005](tech-notes/0005-spm-dependency-isolation-and-vendor-transports.md)) and mobile defense-in-depth principles ([Tech Note 0004](tech-notes/0004-secure-mobile-transport-appcheck.md) and [Tech Note 0010](tech-notes/0010-proxy-transport-and-dynamic-attestation.md)):
- Designed and authored `ProxyTransport: JevTransport, Sendable` in `Sources/JevFoundationModels/Transport/ProxyTransport.swift`:
  - Routes outbound `JevRequest` payloads to an authenticated reverse proxy gateway URL (`proxyEndpoint`) rather than directly contacting upstream cloud endpoints (`api.typesafe.ai`).
  - Completely decouples the core library from vendor SDKs (such as `firebase-ios-sdk`, AWS Amplify, or Auth0) through the `ProxyTransport.Credential` enum:
    - `.bearer(@Sendable () async throws -> String)`: Injects dynamically acquired `Authorization: Bearer <token>` for OAuth 2.0, OIDC, or Firebase Auth tokens.
    - `.header(name:prefix:provider:)`: Injects arbitrary named headers with optional prefixes, such as `X-Firebase-AppCheck: <token>` or `X-Custom-Key: Key <token>`.
    - `.custom(@Sendable (inout URLRequest) async throws -> Void)`: Provides an asynchronous closure hook allowing in-place mutation of the outbound `URLRequest` (e.g. for dynamic HMAC signatures, multi-tenant headers, or custom replay nonces).
  - Built-in retry resilience and backoff:
    - Crucially resolves the credential closure **strictly inside the attempt loop** (`while true`), guaranteeing that short-lived or consumable tokens (such as Firebase App Check limited-use tokens) are freshly minted on every retry attempt rather than failing with stale or already-consumed credentials.
    - Respects RFC 9110 `Retry-After` headers and executes jittered exponential backoff via `RetryPolicy`.
    - Automatically parses upstream service timing headers (`x-envoy-upstream-service-time`) and surfaces gateway latency in `JevResponse.serverDurationMs`.
    - Preserves Swift 6 cooperative task cancellation with clean test seams for clock and sleep injection.

## 🚧 Challenges & Solutions

### 1. Plaintext Secret Leakage in `UserDefaults`
- **Problem**: `KeychainService` mirrored API keys and VPC tokens to `UserDefaults.standard` under `ai.typesafe.secure.storage.*` to retain state during unsigned simulator runs. This wrote credentials into unencrypted `.plist` sandbox files that persist in unencrypted backups.
- **Solution**: Removed all `UserDefaults` credential writes. Enforced hardware-backed storage via Apple's Security framework with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`. Implemented an automatic migration routine on startup that transfers legacy secrets into the Keychain and erases them from `UserDefaults`.

### 2. `#filePath` Sandbox Leaks & Runtime Traversal
- **Problem**: `BackendConfigurationStore.loadKeyFromDotEnv` resolved `#filePath` at runtime and crawled directory hierarchies to find `.env` files. This baked developer workstation paths into Release binaries and triggered sandbox security violations on iOS/macOS.
- **Solution**: Removed `#filePath` and bundle-level upward directory traversal entirely. Credentials in production now flow through user settings in Keychain; in tests/CI, credentials flow strictly via `ProcessInfo.processInfo.environment`, failing fast and visibly when required variables are absent.

### 3. SPM Package Name Discrepancy Blocking Clean Downstream Integration
- **Problem**: When integrating `AppCore` in Xcode and nested SPM tooling, dependencies failed to resolve due to `package: "system-one-laya"` being declared while the root package was named `SystemOneFoundationModels`.
- **Solution**: Standardized the package identity to `SystemOneFoundationModels` in `AppCore/Package.swift`, aligning target dependencies and package manifests.

### 4. Bypassing `@Generable` Boilerplate Without Sacrificing Schema Validation
- **Problem**: Developers asking ad-hoc questions ("Is this spam?") resented writing a 5-line `@Generable struct` for a single boolean. However, directly querying models without a schema bypasses Foundation Models' structured generation guarantees and breaks backend translation in `SchemaTranslator`.
- **Solution**: Created `DynamicDecisionSchema`, which dynamically generates compliant `GenerationSchema` instances at runtime. This allows `session.probability()`, `session.choice()`, and `session.score()` to utilize the standard Foundation Models pipeline (`session.respond(to:schema:)`) under the hood, ensuring identical wire translation across all pluggable backends.

### 5. Infrastructure Boundaries vs. Model Boundaries in Package Traits
- **Problem**: Partitioning traits along infrastructure lines (`CoreML`, `HTTP`, `Networking`, `Tokenization`) leaks internal mechanisms to developers, creates confusing combinatorial configurations (e.g. enabling `Networking` without knowing if it targets Jev or Laya), and risks fractured dependency graphs.
- **Solution**: Partitioned package traits strictly along **model boundaries** (`Jev`, `Laya`, `LayaServe`), matching the developer's mental model ("which model am I running?"). Composed these with high-level persona traits (`OnDevice`, `Remote`, `All`) so mobile developers can simply specify `traits: ["OnDevice"]` to guarantee zero cloud dependencies.

### 6. Calibrated Expected Value Calculation in Ordinal Scoring
- **Problem**: An ordinal rubric score (e.g., levels 0 to 3) cannot simply report the winning discrete bucket when evaluating borderline state (e.g., a case sitting between Level 1 and Level 2). Consumers need both the discrete winner and the probability-weighted continuous mean.
- **Solution**: `ScoreResult` captures the full calibrated probability distribution across rubric levels, returning both the discrete winner (`mostLikelyLevel`, `mostLikelyIndex`) and the continuous expected value (`value = sum(i * p_i)`), matching the precision of Apple Foundation Models rubric evaluation.

### 7. Consumable & Rotating Token Invalidation in HTTP Retry Loops
- **Problem**: When using hardware-attested consumable tokens (such as Firebase App Check limited-use tokens for replay protection) or expiring OAuth bearer tokens, caching a resolved token before entering the retry loop causes every subsequent attempt after a 429 or 401 to fail with an already-used or expired token.
- **Solution**: Evaluated the credential closure dynamically inside the `while true` attempt loop in `ProxyTransport`. Each network retry attempt executes `try await applyCredential(to: &urlRequest)`, ensuring freshly minted or refreshed tokens are attached to every dispatched attempt.

### 8. Reconciling Zero Third-Party Dependencies with Enterprise Mobile Gateways
- **Problem**: Enterprise mobile teams frequently require vendor-specific authentication (Firebase App Check, Cloudflare Turnstile, AWS SigV4, or corporate OAuth). Directly importing these vendor SDKs into `JevFoundationModels` would introduce massive transitive dependency graphs, dragging down clean build times from ~1s to over 45s and creating version lock-in.
- **Solution**: Developed `ProxyTransport` using an open, closure-based `Credential` enum (`.bearer`, `.header`, `.custom`). The core library remains completely free of third-party dependencies (Tech Note 0005 & 0010), while client applications can trivially bridge their vendor SDKs (e.g. `AppCheck.appCheck().token()`) in a single line of closure code.

## 📌 Key Decisions

### 1. Model-Bounded Package Traits with Persona Shorthands (SE-0402)
- **Context**: Swift 6.1 Package Traits allow granular capability management, but improper boundaries cause developer confusion.
- **Decision**: Sliced traits along model boundaries (`Jev`, `Laya`, `LayaServe`) rather than infrastructure boundaries (`CoreML`, `Networking`). Provided persona aliases (`OnDevice`, `Remote`, `All`) and set `Jev` as default.
- **Alternatives Considered**: Slicing by technology stack (`CoreML` vs `URLSession`) — rejected because it leaks internal transport details and fails to express model intent.

### 2. Direct `LanguageModelSession` Extension Over Monolithic Wrappers
- **Context**: Mattt's `AnyDecisionModel` explored type-erased abstractions and custom wrapper sessions.
- **Decision**: Extend Apple's native `LanguageModelSession` directly (`session.probability()`, `session.choice()`, `session.score()`). Developers work with standard Apple Foundation Models types rather than proprietary wrapper classes.
- **Alternatives Considered**: Creating an `AnyDecisionModelSession` wrapper — rejected because it breaks Apple-native ergonomics and composability with other Foundation Models tools.

### 3. Protocol-Driven Categorization with `Choosable`
- **Context**: Enum classification typically requires `@Generable enum`, which requires Swift macro expansion and complex code generation.
- **Decision**: Introduce `Choosable: CaseIterable, Hashable, Sendable` with sensible default identifier implementations (`rawValue` for string enums, `"\(self)"` for standard enums) and optional `optionDescription` for natural language guidance.
- **Alternatives Considered**: Passing raw arrays of strings exclusively — rejected because type-safe Swift enums provide compile-time safety and eliminate typos.

### 4. "Choose Your Path" Tri-Modal Onboarding Architecture
- **Context**: Presenting a single sequential onboarding guide misled developers into believing cloud accounts and API keys were mandatory.
- **Decision**: Structurally bifurcate onboarding into three distinct paths (On-Device Core ML, Local `laya-serve`, and Cloud Jev) in `docs/getting-started.md`. Emphasize zero-dependency offline onboarding first.
- **Alternatives Considered**: Maintaining separate documentation repositories — rejected because unified documentation reinforces the pluggable architecture.

### 5. Dynamic Closure-Based `Credential` Strategy in `ProxyTransport`
- **Context**: Mobile applications use diverse authentication schemes (Bearer tokens, custom headers, App Check, HMAC signing).
- **Decision**: Define `Credential` as an enum containing `@Sendable` async provider closures (`.bearer`, `.header`, `.custom`), providing ultimate flexibility with zero third-party dependencies.
- **Alternatives Considered**: Creating vendor-specific transports (`FirebaseAuthTransport`, `FirebaseAppCheckTransport`) in the core library — rejected to uphold the Zero External Dependencies mandate (Tech Note 0005).

### 6. Per-Attempt Credential Evaluation Inside the Retry Loop
- **Context**: Retrying failed requests requires valid credentials, but tokens can expire during backoff or may be single-use.
- **Decision**: Invoke `applyCredential` on every retry iteration rather than once before loop entry.
- **Alternatives Considered**: Adding token caching logic within `ProxyTransport` — rejected because credential lifetime management belongs to the upstream token provider (e.g., Firebase SDK or OAuth client), not the HTTP transport layer.

### 7. Standalone Trait Samples Matrix (`Examples/TraitSamples/`)
- **Context**: Developers need concrete, copy-pasteable examples of how to consume Swift 6.1 Package Traits in their own `Package.swift` files.
- **Decision**: Author 5 minimal, standalone executable projects in `Examples/TraitSamples/` directly mapped to individual traits (`Laya`, `Jev`, `LayaServe`, `All`, and secure reverse proxying).
- **Alternatives Considered**: Relying solely on Markdown snippets in `README.md` — rejected because executable projects can be validated directly by CI compilers.
