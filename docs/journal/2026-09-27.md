## 🔨 Implementation Trajectory

### 1. Codification of Architectural Directive (`AGENTS.md` Section 7)
- Identified a subtle architectural anti-pattern in the example applications: several sample apps and trait demonstrators quietly fell back to hardcoded closures or `MockJevTransport` when environment variables (`TYPESAFE_API_KEY`, `LAYA_SERVE_URL`, Core ML model files) were absent.
- While well-intentioned for casual inspection, synthetic mocks in example apps produce **false confidence**, hide missing configuration, mask network and serialization errors, and prevent developers from verifying genuine Foundation Models inference.
- Codified **Section 7** in `AGENTS.md` (**Example & Demonstration Applications — NOT Unit Tests — Strict Real Execution**):
  - Example applications and CLI demonstrators in `Examples/` and `Examples/TraitSamples/` are production-representative showcases, **NOT unit tests**.
  - **NEVER implement mock fallbacks, fake offline simulators, or synthetic response bypasses in example apps.**
  - If any required credential (`TYPESAFE_API_KEY`), configuration (`LAYA_SERVE_URL`), or background process (`laya-serve` daemon, Firebase Local Emulator) is missing or unreachable:
    1. Issue a clear, formatted warning banner explaining what is missing.
    2. Provide the exact remediation command (e.g. `export TYPESAFE_API_KEY="..."`, `laya-serve`, or `./run-emulator-and-cli.sh`).
    3. Terminate immediately with `exit(1)`.
  - Mocks are restricted strictly to automated test suites in `Tests/`.

## 🚧 Challenges & Solutions

### 1. Distinguishing Showcase Needs from Unit Test Needs
- **Problem**: Previously, example applications included fallback mock transports so that anyone could run `swift run` without any setup. However, this caused developers to believe they had successfully integrated real models when they were actually executing hardcoded mocks, concealing configuration mistakes and schema mismatches.
- **Solution**: Drew a clean architectural boundary in `AGENTS.md` Section 7: automated unit tests in `Tests/` must be 100% offline and deterministic using mocks, while example applications in `Examples/` must run real models and fail fast with clear instructions when prerequisites are absent.

### 2. Non-Blocking Server Probing in Private Server Sample
- **Problem**: Connecting to an unreachable server in `03-PrivateLayaServer` using standard Foundation Models session calls could hang for default system timeouts (60 seconds) or throw cryptic POSIX connection-refused errors.
- **Solution**: Implemented an explicit `probeServer(url:timeout:)` function utilizing an ephemeral `URLSession` with a tight 2.0-second timeout. If the probe fails, the application immediately outputs the friendly remediation banner without waiting or crashing.

### 3. Aggregating Multi-Prerequisite Errors in Hybrid Router
- **Problem**: `04-HybridRouter` requires both local on-device assets (compiled Core ML model) and cloud credentials (`TYPESAFE_API_KEY`). Checking them sequentially would force users to fix one, run again, and discover the next missing item.
- **Solution**: Created a validation pipeline that collects all missing prerequisites (`missingPrerequisites: [String]`, `remediations: [String]`) and renders a single unified banner showing all missing items and their corresponding export commands before exiting.

## 📌 Key Decisions

### 1. Strict Real Execution Mandate (AGENTS.md Section 7)
- **Context**: Demonstrators and samples should prove actual integration works.
- **Decision**: Prohibit synthetic mock fallbacks in all example applications. If prerequisites are not met, issue remediation instructions and exit with code 1.
- **Alternatives Considered**: Keeping offline mode behind an explicit flag like `--mock` — rejected because example code should show real production wiring, not mock routing logic.

### 2. Standardization on Exit Code 1
- **Context**: CLI tools need clear status signaling for shell scripts and developers.
- **Decision**: Terminate unconfigured runs with `exit(1)` immediately following the formatted banner.
- **Alternatives Considered**: Throwing unhandled Swift errors — rejected because raw runtime stack traces look like bugs rather than actionable configuration guidance.
